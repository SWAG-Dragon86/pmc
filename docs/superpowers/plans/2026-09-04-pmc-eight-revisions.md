# PMC 九项修订实施计划（含追加友情防守）

**Goal:** 同步修复网页版与安卓 APP，交付同签名 1.1.0 APK；不发布公网，不删除用户记录。

**Architecture:** 新增独立开局处理模块，原始场景只作输入；开局事件按概率生成状态，交给原有整数 HP 回合引擎。过程汇总在每个行动结束时记录，不用一个代表分支冒充全部过程。分享图读取结构化结果。

**Tech Stack:** React / Vite / Node test / Canvas / Android Java WebView。无新增依赖。在当前任务顺序执行；未提供的 executing-plans 子技能以本清单及现有测试框架替代。

## 已确认规则

1. 开局天气：所有在场且存活的天气特性参与，不受守住影响。性格、能力点、道具计入开局速度，速度阶段、麻痹、顺风、戏法空间不参与。同速不同天气分别算；默认自动，允许手动覆盖。
2. 性格显示增减项；内敛、固执、胆小、爽朗、大胆、温和按此顺序置顶。
3. 突袭假定满足成功条件，保留正常免疫及守住；劈瓦破除墙后影响自己与后续攻击。
4. 不服输 / 好胜：先降后升；开局威吓及出手前受到对方必定降能力效果触发。概率降能力不触发这两项试算，后续变化不追溯已完成攻击。不添加未实装的甘露之蜜。
5. 威吓开局每只触发一次，面向对方在场宝可梦；遵循能力下降免疫，手填等级为触发前值，不改配置库。
6. 导出图：主目标剩余 HP / 击倒率，按行动顺序列每击伤害与剩余 HP。其它位置最终 HP 摘要；保留关键反伤、误伤及简短有效配置。默认汇总，另可导出分支详情。
7. 双方独立隐形岩开关、撒菱 0-3 层，HP 输入为吃钉前；先入场扣血再攻击。不添加逐只入场开关。
8. 安卓及网页横竖屏自适应，背景与布局一起切换；提供安卓旋转处理，不改变系统全局设置。
9. 友情防守保留可手动操作的开关；队友特性符合时自动勾选。

旧场景保留原值，首次加载提醒核对威吓前等级；保存新场景带开局规则标记。

## 根因记录

天气 / 威吓在旧引擎不自动触发；不服输好胜列入未适配名单；突袭劈瓦列入复杂招式名单。图片把完整配置串行堆叠，只报告最终 HP，代表分支日志不能证明所有概率路径。横屏背景已有媒体查询，但原生方向依赖系统锁定且小屏横屏没有专用排版规则。以实际模拟器复现进一步区分两层问题。
