The conservative distribution approach retains that license, supplies the pinned dictionary source and generation scripts, and distributes the combined program under GPL-compatible conditions. PMC's own GPL-3.0-or-later choice does not expand a third party's GPL-3.0-only grant. Where applicable, the combination can be distributed under GPL version 3. Preserve upstream copyrights and license texts.

For a compiled website or APK release, publish the matching source revision, dependency lockfile, vendor snapshots and build instructions, together with the applicable notices. A release must identify its actual source revision; a link to an unrelated future branch is insufficient. Never include private signing keys, credentials, local user backups or development caches as corresponding source. The maintainer must assess any applicable installation-information obligation before distributing a modified binary for a locked-down user product. This task creates an unsigned verification artifact, not a new public binary release.

## Confirmed code-license decision and long-term effect

The maintainer reaffirmed GPL-3.0-or-later during final preparation on 2026-10-23. This is the selected license for maintainer-owned code; it is not a temporary MIT proposal. Recipients may run, modify, fork and redistribute that code, including commercially, provided they comply with the license. When distributing covered modified works, preserve notices, identify changes, keep the applicable GPL terms and provide the matching Corresponding Source. A public website delivers JavaScript to visitors; a public binary APK also needs its applicable source/notice obligations addressed.

The GPL grant is irrevocable for compliant recipients of an already licensed copy (GPL section 2). The maintainer still owns their own copyright, but cannot retract those existing grants. Re-licensing future versions requires authority over the affected contributions, and does not remove the upstream Chinese dictionary's GPL terms. The “or later” option permits recipients to choose a later FSF GPL for the code so designated (section 14); it does not expand a third party's GPL-3.0-only grant. A combined release can use GPL version 3 where that satisfies all components. Private internal changes do not automatically require publication merely because GPL is used; actual distribution matters.

Code and independent artwork can carry different licenses when their actual relationship permits this. Separate paths/notices help explain scope but do not, on their own, establish legal independence or clear artwork rights. A noncommercial restriction on images must never be described as a restriction on the GPL code itself. The maintainer confirmed PMC is free, not sold and intended as a noncommercial open-source tool. This makes noncommercial community-art licenses a candidate to examine, not an automatic grant for existing game rips.

## Adopted sources and excluded alternatives

[SpriteCollab's contributor policy](https://github.com/PMDCollab/SpriteCollab#readme) and [LICENSE.md](https://raw.githubusercontent.com/PMDCollab/SpriteCollab/master/LICENSE.md) permit noncommercial sharing and adaptation of contributor material under CC BY-NC 4.0 with attribution. The selected contributor frames are now incorporated as recorded in ASSET_CREDITS.md. The repository also contains official Chunsoft sprites/portraits, so check each selected file's provenance and credits; do not assume the contributor grant covers official originals or all underlying character rights. All 350 catalog IDs now have contributor permission records. Two Gourgeist sizes use a shared species portrait explicitly approved by the maintainer; separate form data and calculations are retained. CC BY-NC artwork must remain separately licensed; it is not GPL artwork and is not an unrestricted open-source asset license.

[PokéSprite](https://github.com/msikma/pokesprite#license) offers free downloads but explicitly excludes sprite images from its MIT code grant. It does not resolve the current rights gap by itself. Official press assets have a [limited media license](https://pokemon.gamespress.com/Media-Usage-Guidelines), not a blanket transfer/sub-license for this software's repository, APK and user-exported cards.

The already-used [Lucide icons](https://lucide.dev/license) have explicit ISC/MIT permissions with notices. They can support generic type/UI symbols without a new dependency, but are not Pokémon portraits. The maintainer confirmed the existing background was created by the project. It remains unchanged and is no longer classified as an unknown third-party source; no separate standalone reuse license is inferred.

On 2026-10-23 the maintainer explicitly authorized finding and replacing appropriately licensed noncommercial artwork. The maintainer subsequently authorized deletion of the Strange Ball, cleanup of old artwork history, and source/Pages updates to both existing GitHub and GitLab repositories. The original history and files remain in local ignored backups; they are not included in the published branch.
